# ダメ出し台帳

ユーザーから受けたダメ出しを1行ずつ追記する。新しいLPを作る前に必ず読む。
書式：`- [YYYY-MM-DD] 何をしない／何をする（理由）`

- [2026-10-07] 年収1000万円の訴求はしない。平均年収など実績の数字はOK（田中の指示）
- [2026-10-07] 職種名を名指しする（「TikTokマーケターになりたい人」型）。抽象的な呼びかけは弱い（HADOの動画CR実績）
- [2026-10-07] 写真は仕事が見えるものだけ。仕事と関係ないライフスタイル写真は応募の質を落とす（動画CRで予約率10%に落ちた）
- [2026-10-07] OFFER.md にない事実（工期・面談の曜日・休憩時間など）を本文で断定しない。書くならOFFERに足してから（作例の採点で「作り直す」になった）
- [2026-10-07] 「履歴書不要」など、ページ内で何度も言う約束は最後まで一貫させる。選考フローで覆すと信頼が消える（採点で一番損をする箇所に挙がった）
- [2026-10-07] 募集要項の表（勤務時間・応募資格・試用期間・保険・交通費・手当の条件）は必ず入れる
- [2026-10-07] 同じ数字の演出（寸法線など）は1ページ1回。2回出すと弱くなる
- [2026-10-14] HADO自社の採用LPは、HADOコーポレートサイト（hado.co.jp）のトーンで作る：明るいグレー#F1F3F6＋白・文字#191919・青#1E60E0・大きな英字見出し（Archivo）＋小さな日本語。TikTokのネオン（シアン/ピンク・ズレ影）は「TikTokすぎる」、資料用の紺/橙も「違う」と言われた
- [2026-10-23] 公開前に `node scripts/check.mjs` で320〜430pxの全幅を機械検査し「全幅OK」が出るまで出さない。目視だけに頼らない（NSC様LPのスマホ表示を巡る混乱から）
- [2026-10-23] スマホのスクショは Playwright のスマホ指定（scripts/shot.mjs・check.mjs）で撮る。headless Chrome の --window-size=390 は約500px未満に縮まらず右が切れて写る＝誤検知のもと
